# Project Naming Skill

## Purpose
Help people choose short, memorable, professional project aliases while keeping a clear connection to a formal project title and an optional permanent identifier.

## When to use
Use for requests to:
- Name a new initiative or project.
- Generate project aliases/codenames.
- Rename or assess an existing project name.
- Develop a consistent naming framework for multiple projects.
- Avoid duplicate or confusing project names in a portfolio.

## Inputs
Use any information already supplied. If details are missing, still generate useful preliminary candidates rather than insisting on a questionnaire.

Preferred information:
- **Purpose:** problem being solved or outcome sought.
- **Context:** business area, audience, culture, industry.
- **Type:** transformation, operational improvement, technology, integration, innovation, compliance, etc.
- **Tone:** formal, energetic, aspirational, discreet, technical, etc.
- **Constraints:** words to avoid, naming themes, length, language, existing names.
- **Existing aliases:** for collision checks (if provided).
- **Project ID:** optional permanent identifier supplied by a project register; never invent an official ID.

If a single crucial ambiguity prevents an appropriate suggestion, ask one concise question. Otherwise proceed with stated assumptions.

## Naming principles
1. **Clear separation:** Formal title describes the work; alias makes it memorable; project ID uniquely identifies the record.
2. **Brevity:** Prefer one word with 1–3 syllables; two words only when markedly better.
3. **Pronounceability:** Easy to speak, spell, hear in meetings, and search in messages.
4. **Relevant metaphor:** Subtly suggest intended direction, capability, or outcome without being painfully literal.
5. **Distinctiveness:** Avoid names that resemble one another or existing initiatives.
6. **Durability:** Avoid vendors, transient technologies, specific years, internal team names, or implementation solutions likely to change.
7. **Professionalism and cultural fit:** Avoid offensive, insensitive, boastful, militaristic, or confusing connotations; consider international pronunciation and meaning.
8. **No forced backronyms:** Do not invent expansions for aliases unless explicitly requested.
9. **Honesty:** Do not claim trademark, domain, or internal-name availability without an actual check.

## Naming themes
Choose a theme that fits the purpose; do not make all names sound alike.

| Theme | Typical fit | Illustrative names |
| --- | --- | --- |
| Navigation | strategy, transformation | Compass, Beacon, Horizon |
| Momentum | productivity, delivery | Pulse, Swift, Momentum |
| Connection | integration, collaboration | Bridge, Nexus, Weave |
| Discovery | innovation, exploration | Nova, Orbit, Spark |
| Strength | stability, foundations | Granite, Summit, Anchor |

Examples are inspiration, not an approved or available name inventory.

## Workflow
### Step 1 — Capture the brief
Summarise the project's core outcome in one sentence. Identify audience, desired tone, and 2–3 useful metaphors or naming themes.

### Step 2 — Generate broadly
Create 10–15 distinct candidates internally, spanning at least 2 themes when constraints permit. Avoid near-duplicates, generic project buzzwords, and aliases that require elaborate explanation.

### Step 3 — Screen
Reject candidates that are difficult to pronounce, have obvious negative associations, clash with supplied existing names, overpromise benefits, or lock the initiative to a temporary solution.

### Step 4 — Score the shortlist
Assess each remaining candidate against the following weighted rubric (1–5 each):

| Dimension | Weight |
| --- | ---: |
| Memorable and pronounceable | 30% |
| Relevant to project purpose | 25% |
| Distinctive within portfolio | 20% |
| Professional and culturally suitable | 15% |
| Future-proof | 10% |

Compute weighted scores out of 5 if a ranked comparison is requested. The scores are judgment aids, not objective measurements. Do not assert portfolio distinctiveness without an existing-name list.

### Step 5 — Recommend
Present 5 strong choices by default, with a one-line rationale for each, then recommend one preferred alias with 1–2 sentences on why it fits. Include different styles instead of 5 synonyms.

### Step 6 — Structure official use
When useful, present:
- **Formal project name:** descriptive business title.
- **Alias:** `Project <Alias>`.
- **ID:** `Use existing register ID` unless a real ID was provided.
- **Register label:** `<ID> | Project <Alias> | <Formal name>` (omit ID if unavailable).
- **One-line description:** what outcome the project pursues.

### Step 7 — Validate before adopting
Suggest checking the proposed alias against the internal project register, product or brand names, key stakeholder associations, cross-language sensitivities, and external trademarks where applicable. Never imply these checks were completed unless they were.

## Response formats

### For naming a single project
1. **Project interpreted as:** one-sentence summary; list any consequential assumptions.
2. **Top 5 aliases:** table with alias, meaning, and tone.
3. **Recommended:** one clear winner and why.
4. **Use it like this:** formal title + alias (+ actual ID if supplied).
5. **Check before launch:** relevant collision/sensitivity checks.

Keep the initial answer concise and practical; offer a wider list only if useful.

### For building a portfolio convention
Include naming syntax, allowed theme families, do/don't rules, ownership/approval, duplicate-check process, register fields, and five sample entries. Recommend a stable unique project ID and prohibit reuse of retired IDs. Do not require every alias to start with the same letter or hide meaning in artificial acronyms.

### For evaluating existing aliases
Score supplied names using the rubric, flag confusion risks and unwanted connotations, recommend a winner, and suggest replacements only where needed.

## Example
**Request:** Name a project improving spare-parts availability and reducing delivery delays.

**Formal name:** Parts Availability and Delivery Improvement

| Alias | Why it fits |
| --- | --- |
| Swift | Implies shorter turnaround times |
| Beacon | Suggests better visibility into availability |
| Bridge | Connects demand with supply |
| Pulse | Signals timely operational response |
| Compass | Suggests dependable direction and coordination |

**Recommendation:** Project Swift — concise and outcome-oriented, provided it does not conflict with an existing initiative.

**Register entry:** `Project Swift | Parts Availability and Delivery Improvement` (append the real project ID when assigned).

## Final quality check
Before answering, ensure:
- Shortlist is non-repetitive and fits the brief.
- Alias is clearly distinct from formal name.
- Recommendation has a specific rationale.
- No fictitious ID or unverified availability claim appears.
- Names can be spoken comfortably in a status meeting.
